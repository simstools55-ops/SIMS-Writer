# SERP Gap Report v2.1

SERP Gap Reportは、修正案の前に利用者へ示す短い比較要約である。診断レポートではない。

表示する内容:
- 比較できたページ数（実測できた場合のみ）
- 現在の記事で十分に扱えている強み
- 検索意図上重要で不足または弱かった点
- Gapごとの重要度（★1〜5）
- 今回補う点
- 今回補わない点と簡潔な理由
- 修正決定までの短いDecision Trace

## 定量表示ルール

- `比較10件`、`8/10件`などは、実際に個別確認したページ数と掲載数だけを書く。
- 正式順位を確認できない場合は「確認できた上位ページ5件」のように事実どおり表現する。
- 件数を数えていない場合は数値を出さない。推測値、概算値、慣用的な「上位10件」を作らない。
- 競合URL一覧は利用者へ表示しない。

## Gap重要度

重要度は次の4要素を統合して1〜5で決定する。
1. Search Consoleで需要が確認できるか。
2. 確認済みSERPで共通して扱われているか。
3. 自記事で不足・弱いか。
4. 公開に必要なEvidenceがあるか。

- ★★★★★: 中心意図で需要・SERP共通性・自記事不足が明確。優先対応。
- ★★★★☆: 重要な副次意図で不足が明確。原則対応。
- ★★★☆☆: 有用だが中心意図ではない。記事構成とEvidenceを見て判断。
- ★★☆☆☆: 補助的。今回見送り可能。
- ★☆☆☆☆: 関連が弱い、別意図、または採用価値が低い。

Evidence不足の項目は重要度が高くてもPUBLIC_OKへは昇格させず、USER_DECISIONまたはINTERNAL_REJECTとする。

## Decision Trace

利用者向けDecision Traceは3〜5行の短い流れにする。例:
- Search Consoleで「追加できない」の需要を確認
- 確認した上位8件中6件が原因と対処を扱う
- 現在記事では回答が弱い
- 公式根拠がある範囲だけ公開OKへ反映

内部スコア、Evidenceコード、監査ログ、生の思考過程は表示しない。
